# SPEC: шаблон Remotion для игровых нарезок (TikTok / Shorts)

> Положи этот файл в корень проекта (`SPEC.md` или `CLAUDE.md`) и напиши Claude Code:

---

## 0. Цель

Шаблон, который из **одного исходного файла** (вебка сверху + геймплей снизу уже склеены, как в моих роликах) делает вертикальный ролик для TikTok / Shorts:

- **монтаж строится от смысла монолога, а не от чужого референса**: сначала анализ того, что я говорю (тема, хук, кульминация, ключевые слова, вода), и уже из него решения о вырезках, акцентах и ритме,
- быстрый монтаж (смена картинки каждые 1–2 сек там, где это уместно по смыслу),
- **акценты на эмоциях** (вебка крупно) и **на геймплее** (зум/тряска): выбираются по смыслу, тайминг уточняется по звуку,
- **пословные субтитры с анимацией** на основе Whisper,
- **мат заглушается и закрывается звуком «кря»**,
- мёртвые куски (чёрный экран смерти, тишина) вырезаются,
- музыка и SFX из моей папки `assets/`.

Это **шаблон на все ролики**: стиль задан один раз, новые клипы просто подкладываются.

Рабочий процесс: `prep` (звук, Whisper) → `analyze` (анализ смысла монолога) → `studio` (правки) → `render`.

## 1. Правила для Claude Code

1. Версии Remotion и пакетов быстро меняются. **Перед написанием кода сверься с актуальной документацией Remotion** (remotion.dev/docs) и версией, которая реально стоит в `package.json`. Не опирайся на память об API.
2. Если `package.json` нет, создай проект: `npx create-video@latest` (шаблон Blank, TypeScript).
3. Работай по шагам из раздела 10. После каждого шага запускай проверку и коротко сообщай результат.
4. **Не выдумывай файлы.** Если в `assets/` нет нужного звука, пропусти этот эффект, предупреди меня и продолжай.
5. Все пороги и параметры выноси в `config.json`, а не в код: я буду их подкручивать.
5a. **Исходники бывают любой длины** (от нескольких секунд до десятков минут). Не завязывайся на длительность, размер файла или число слов: длительность композиции, число субтитров, акцентов и вырезок всегда считаются из `data.json`. См. раздел 8а.
6. Перед полным рендером делай пробный рендер 3–5 сек (`--frames=0-150`) и проверяй результат.
7. Не удаляй и не перезаписывай мои исходники в `input/` и `assets/`.

## 4. Раскладка кадра

Источник уже склеен: **вебка сверху ≈32% высоты, геймплей снизу ≈68%** (по моему ролику). Это константы в `config.json` и их нужно откалибровать по кадру.

Одну и ту же дорожку видео рисуем **двумя слоями** (два `<OffthreadVideo>` с обрезкой через `overflow: hidden` и `transform`), звук берём только с одного (второй `muted`):

- слой **webcam**: верхняя часть исходника;
- слой **gameplay**: нижняя часть исходника.

Состояния раскладки (плавные переходы через `spring`, 6–8 кадров):

| Состояние | Вебка | Геймплей | Когда |
|---|---|---|---|
| `default` | ≈35% высоты | ≈65% | обычный ход |
| `emotion` | ≈55% высоты, зум 115% по центру лица | ≈45% | эмоциональный пик голоса |
| `gameplay` | ≈20% высоты | ≈80%, zoom-punch 100→120→105% за ~0.2 сек, shake 4–6 кадров | резкий игровой момент |

Лицо и ключевое действие должны оставаться в кадре (центрировать зум, не обрезать лицо).

## 5. Автоматические акценты (по звуку)

**Это вторичный сигнал.** Главные решения о монтаже принимаются по смыслу монолога (раздел 5а), а звуковые пики уточняют точный тайминг внутри смысловых моментов и служат запасным вариантом, если `analysis.json` нет.

Анализ в `prep`: окна по ~100 мс, уровень RMS в dBFS (ffmpeg или декодирование wav в Node).

- `baseline` = медианный уровень по клипу. Для длинных исходников считай **скользящий baseline** (окно ≈ 30–60 сек, `config.json → accents.baselineWindowSec`), чтобы громкие и тихие части клипа не искажали пороги друг друга. Для коротких клипов (< 30 сек) используй один общий baseline.
- **`emotion`** (крики, смех, повышенный голос): уровень > `baseline + 8 dB` и держится ≥ 300 мс.
- **`gameplay`** (выстрел, взрыв, резкий звук игры): короткий пик (< 200 мс) > `baseline + 12 dB`.
- Пауза между акцентами ≥ 1.5 сек; суммарно акценты не больше ~40% ролика.
- Каждому акценту добавляется `start`, `end` с запасом 0.15 сек, `type`.

Результат пишется в `data.json → accents[]`. **Я могу править этот массив вручную** в Studio / файле: добавлять, удалять, менять тип.

Честное ограничение: звук в исходнике смешан (голос + игра), поэтому автоматическое разделение «голос / игра» приблизительное. Пороги нужно подбирать по моим клипам, держи их в `config.json`.

## 5а. Анализ смысла монолога (главный источник решений о монтаже)

**Принцип:** монтаж строится на сути того, что сказано, а не на копировании стиля референса. Визуальный каркас (шрифты, цвета, типы переходов) фиксирован в этом файле и в `config.json`. А вот **что вырезать, где поставить хук, на чём сделать акцент и когда замедлить**, определяется анализом монолога.

**Как:** после `prep` Claude Code сам читает `data.json → words[]` (транскрипт с таймкодами) и пишет `public/<clip>/analysis.json`. Внешние API не нужны: анализатором является сам Claude Code. Длинный транскрипт читай кусками и держи короткую сводку, чтобы не потерять сквозную линию рассказа.

### Что нужно определить

1. **Тема и жанр:** фейл, рассказ, реакция, совет, спор, обзор, юмор.
2. **Смысловые сегменты:** подводка (setup), развитие, кульминация или панчлайн, развязка. Для каждого `start/end`, роль и одно предложение сути.
3. **Хук:** самая цепляющая фраза или момент (не обязательно из начала). Предложи его как открытие первых 1.5 сек. Порядок не менять без моего подтверждения (см. раздел 8).
4. **Ключевые слова и фразы** для выделения в субтитрах: панчлайны, цифры, имена, эмоциональные слова, неожиданные повороты.
5. **Эмоциональные пики по смыслу:** шутка, возмущение, удивление, разочарование, смех, с оценкой интенсивности 0–1.
6. **Вода:** слова-паразиты («ну», «э», «короче»), оговорки, дубли фразы, повторы, отступления от темы. Это кандидаты на вырезку или ускорение, у каждого есть причина.
7. **Связь с игрой:** фразы вроде «смотри», «ты видел», «блин», «вот это» указывают на игровой момент. По ним ставится `gameplay`-акцент (точный тайминг уточняется по звуковому пику).
8. **Ритм по смыслу:** плотные и эмоциональные места режутся чаще, объяснения и подводка идут спокойнее.

### Как смысл превращается в монтаж

| Что нашёл анализ | Что делает монтаж |
|---|---|
| Хук | выносится в начало (первые 1.5 сек), крупное слово в субтитре |
| Подводка (setup) | раскладка `default`, умеренный темп, паузы ускоряются |
| Кульминация / панчлайн | акцент `emotion` или `gameplay`, slow-mo или повтор, SFX, 0.5–1 сек тишины перед |
| Ключевое слово | выделение цветом и размером в субтитре |
| Эмоциональный пик (смех, крик, возмущение) | раскладка `emotion` |
| Вода, повторы, оговорки | вырезка или ускорение, причина записана в `analysis.json` |
| Упоминание игрового момента | акцент `gameplay` в момент события |
| Мат | раздел 7 |

### Правила

- **Не вырезать то, без чего ломается смысл** или логика шутки. Перед вырезкой проверь, что соседние фразы склеиваются связно.
- Каждое решение в `analysis.json` содержит `reason` (одно предложение) и `confidence` (0–1), чтобы я мог быстро проверить его в Studio.
- **Не придумывать.** Если смысл неясен (шум, неразборчивая речь, низкая уверенность Whisper), пометь `confidence` низким и оставь этот участок со стандартным монтажом.
- Анализ идёт по **тексту и звуку**, картинку Claude Code по умолчанию не видит. Связь с игровым моментом строится по словам и звуковым пикам. Если нужна проверка по картинке, можно вытащить кадры через ffmpeg и посмотреть их, но это опция, а не поведение по умолчанию.
- `analysis.json` я могу править вручную. Композиция и `render` читают только его (плюс `data.json`), так что любое моё изменение сразу влияет на результат в Studio.

### Формат `analysis.json` (времена в секундах исходника)

```json
{
  "topic": "кратко, о чём ролик",
  "genre": "fail",
  "hook": { "start": 12.4, "end": 13.9, "text": "...", "reason": "...", "confidence": 0.8 },
  "segments": [
    { "start": 0, "end": 8.5, "role": "setup", "summary": "...", "pace": "medium" },
    { "start": 8.5, "end": 14.0, "role": "climax", "summary": "...", "pace": "fast" }
  ],
  "keywords": [ { "wordIndex": 42, "reason": "панчлайн", "confidence": 0.9 } ],
  "peaks": [ { "start": 12.4, "end": 13.4, "kind": "laugh", "intensity": 0.8, "reason": "..." } ],
  "cuts": [ { "start": 3.1, "end": 4.0, "action": "cut", "reason": "слово-паразит и пауза", "confidence": 0.7 } ]
}
```

`action` в `cuts`: `cut` (вырезать) или `speedup` (ускорить, с полем `speed`).

## 6. Субтитры (Whisper, пословные)

**Транскрипция** внутри проекта (`prep`):

1. Из клипа вытащить 16 kHz mono WAV через ffmpeg.
2. Запустить Whisper через пакеты Remotion (`@remotion/install-whisper-cpp`, `@remotion/captions` — сверься с докой). Язык `ru`, пословные таймстемпы, модель `medium` или лучше (`large-v3-turbo`, если потянет). **Для длинных исходников** (дольше ≈ 5 мин) режь аудио на куски по 2–5 мин с небольшим нахлёстом (≈ 1 сек), транскрибируй по очереди и склей слова обратно с поправкой на смещение времени, убирая дубли на стыках. Покажи прогресс в консоли.
3. Сохранить слова с `start/end` в `data.json → words[]`.

**Внешний вид:**

| Параметр | Значение |
|---|---|
| Шрифт | Montserrat ExtraBold (`@remotion/google-fonts`) или Anton / Bebas Neue |
| Размер | 80–90 px |
| Регистр | ЗАГЛАВНЫЕ |
| Цвет | белый `#FFFFFF`, активное слово жёлтое `#FFD400` |
| Обводка | чёрная 8 px (`paintOrder: stroke fill`) + мягкая тень |
| Позиция | ≈62% высоты кадра, по центру; не заходить в зоны интерфейса платформ (верх ~150 px, низ ~250 px) |
| На экране | 1–3 слова за раз |

**Анимация:** слово «выскакивает» в момент произнесения (scale 0.8 → 1.1 → 1 за 4–6 кадров). Эмоциональные слова (по `emotion`-акценту или восклицанию) на 15–25% крупнее и с небольшой тряской. Цветов за ролик не больше 2–3.

**Важно:** после вырезок мёртвых кусков (раздел 8) все таймкоды слов нужно пересчитать (remap из исходного времени в выходное).

## 7. Мат → «кря»

1. В `profanity.txt` лежит список слов и корней мата. Сравнение по нормализованным словам из Whisper (нижний регистр, без знаков, с учётом форм слова по корню).
2. Для каждого найденного слова берём `start/end` из Whisper.
3. **Звук:**
   - в окне `[start − 2 кадра, end + 1 кадр]` приглушаем звук (`volume = 0` через функцию от кадра в `<Audio>`);
   - в то же время играем «кря» из `assets/sfx/quack*.mp3` (случайный из имеющихся, длительность подгоняем под слово, 0.2–0.4 сек; длинное слово можно закрыть двумя короткими);
   - «кря» по громкости на уровне голоса, чуть выше.
4. **Субтитр:** слово заменяется на **«КРЯ»** (с «попом» и тряской, жёлтый цвет). Оригинал мата на экране не показываем.
5. Если мата слишком много (чаще 1 раза в 3–4 сек), сообщи мне в отчёте `prep`, не закрывай всё подряд автоматически. Предложи закрыть самые сильные, остальные вырезать монтажом.
6. Мат в **первые 5 секунд** ролика отметь в отчёте отдельно (может ограничить показы).

**Ограничение:** исходник со смешанным звуком. Заглушить только голос, не тронув игру, нельзя: во время «кря» просядет весь звук на 0.2–0.4 сек. Если у меня будет отдельная дорожка микрофона, используй её для глушения только голоса (поддержку заложи в `config.json`: `voiceTrack`).

## 8. Вырезка мёртвого времени и темп

Автоматически в `prep` (каждый пункт включается флагом в `config.json`):

- **Чёрный экран / экран смерти:** ffmpeg `blackdetect` или анализ яркости кадра нижней части. Сегменты > 0.5 сек вырезаются. Максимум можно оставить 0.3–0.5 сек как freeze-кадр с SFX (`error.mp3`).
- **Тишина и пустые паузы:** сегменты, где голос тих и в кадре нет действия, длиннее 1 сек ускоряются ×2–×3 или вырезаются.
- **Вырезки по смыслу:** список `analysis.json → cuts` (вода, повторы, оговорки) применяется вместе с техническими вырезками выше. Если они пересекаются, объединяй сегменты.
- **Начало ролика:** хук выбирается по смыслу (`analysis.json → hook`, раздел 5а). Если начало слабое, предлагай перенести хук в начало и покажи как вариант в отчёте. Не меняй порядок без моего подтверждения.
- Итоговый тайминг хранится как список «оставленных сегментов» `[srcStart, srcEnd, speed]`; композиция собирается через `<Series>` / `<Sequence>`. Вся остальная логика (акценты, слова, мат) работает в **выходном** времени через remap.

**Темп:** смена картинки/акцента в среднем раз в 1–2 сек, прямые склейки ≈70%, эффектные переходы редко (свуш 4–6 кадров, зум-пуш, glitch 3–5 кадров).

## 8а. Исходники разной длины

Длина исходника разная, поэтому поведение зависит от неё и задаётся в `config.json → length`:

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `mode` | `"keep"` | `"keep"` = оставить всё, что не вырезано (длина ролика получается сама); `"fit"` = ужать до `targetSec` |
| `targetSec` | `null` (для `fit`: 30) | желаемая длина ролика |
| `maxSec` | `60` | предупреждать, если итог длиннее (TikTok / Shorts лучше держать короче) |
| `minSec` | `5` | предупреждать, если итог короче |

**Правила:**

- Любая длина исходника поддерживается: длительность композиции (`calculateMetadata`), число субтитров и акцентов вычисляются из `data.json`.
- `mode = "keep"`: если после вырезок ролик длиннее `maxSec`, `prep` **не режет сам**, а пишет предупреждение в отчёт и показывает, где самые «пустые» участки.
- `mode = "fit"`: `prep` выбирает лучшие моменты (по плотности акцентов: громкие пики голоса и игры, смех) и собирает ролик ≈ `targetSec` из нескольких кусков с запасом 1–2 сек до и после каждого момента. Результат — список сегментов в `data.json`, который я могу поправить в Studio.
- Очень короткий исходник (< 5 сек): без ускорения и вырезок, только субтитры и акценты.
- Длинный исходник: временные файлы (WAV, кадры анализа) хранить в `public/<clip>/tmp/` и не загружать целиком в память, анализ по окнам/потоком.
- Отчёт `prep` выводит: длина исходника, длина после вырезок, число слов, акцентов, найденного мата, предупреждения.

## 9. Звук

| Слой | Правило |
|---|---|
| Исходный звук | нормализовать в `prep` до ≈ −14 LUFS (мои исходники тихие, средняя ≈ −31 dB) |
| Музыка | `assets/music/*`, громкость ≈ −22 dB (линейно ≈ 0.08), ducking под голос, на бит, если возможно |
| SFX | свуш на переходах/акцентах, `boom`/`error` на фейле, щелчок слов (очень тихо) |
| «Кря» | см. раздел 7 |
| Тишина | 0.5–1 сек приглушения перед пиком фейла, затем громкий SFX |

Названия файлов задаю я, а Claude Code **читает содержимое папок** и использует то, что есть. Если папка пуста, эффект выключается с предупреждением.

## 10. План работ (по шагам)

1. **Скелет:** проект Remotion, структура папок, `config.json`, npm-скрипты.
2. **Раскладка:** композиция 1080×1920 с двумя слоями (вебка / геймплей) из одного файла, калибровка пропорций.
3. **`prep`:** нормализация звука, WAV, Whisper, `data.json` со словами.
3а. **Анализ монолога (раздел 5а):** Claude Code читает транскрипт и пишет `analysis.json` (хук, сегменты, ключевые слова, пики, вырезки с причинами). Показать мне краткую сводку перед сборкой.
4. **Субтитры:** пословные, анимация, стиль из раздела 6.
5. **Акценты:** анализ звука, состояния раскладки, zoom-punch, shake.
6. **Мат → «кря»:** детекция, глушение окна, SFX, замена слова в субтитре.
7. **Вырезка мёртвого времени** + remap таймкодов.
8. **Музыка и SFX** из `assets/`.
9. **Studio:** проверить, что `accents`, `words`, список вырезок можно править и сразу видеть результат.
10. **Рендер:** `npm run render -- <clip>` и пробный клип 3–5 сек перед полным.

## 11. Чек-лист готового ролика

- [ ] 1080×1920, 30 fps, длина соответствует `config.json → length` (по умолчанию не больше ≈60 сек, идеал 15–35)
- [ ] Хук в первые 1.5 сек
- [ ] Нет кадров дольше ≈3 сек без события, чёрный экран смерти вырезан
- [ ] Монтаж следует смыслу монолога: хук, кульминация и ключевые слова выделены, вырезана только вода
- [ ] Ни одна вырезка не ломает логику фразы или шутки
- [ ] Акценты срабатывают на настоящих эмоциях и действии, а не на шуме
- [ ] Субтитры пословные, попадают в слова, не заходят в зоны интерфейса
- [ ] Весь мат закрыт «кря», на экране «КРЯ», в первые секунды мата нет
- [ ] Голос слышно над музыкой, общий уровень ≈ −14 LUFS
- [ ] Лицо и действие не обрезаны на зумах
